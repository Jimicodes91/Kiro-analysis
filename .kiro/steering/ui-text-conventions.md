# UI Text Conventions

Follow these rules for all user-facing text in the Pylott frontend to maintain a professional, consistent look.

## Page Headings (Title Case)
- All page-level headings (`<Heading size="h3">`) MUST use Title Case
- Plural form for list/index pages: "Projects", "Tasks", "Contacts", "Events"
- Singular + descriptor for detail pages: "Project Details", "Company Information"
- Action pages: "Create New Task", "Add Project"
- Examples: "Profile Settings", "Finance & Billing", "Subscription Plan"

## Section Headings & Labels (Title Case)
- All section headings (`<Heading size="h5">`, `<h3>` labels) MUST use Title Case
- Examples: "Subscription Plan", "Project Settings", "Notification Preferences"
- Field labels: "Created Date", "Industry Type", "Total Fee", "Last Payment Date"

## Admin Tab Labels (Title Case)
- All tab labels MUST use Title Case: "Users", "Journey", "Document Type", "Event Type", "Note Type", "Task Type", "Audit Trail"

## Empty States (Sentence Case)
- Empty state headings use sentence case with plural nouns: "No tasks to show yet", "No contacts to show yet"
- Body text must be grammatically correct: "We'll let you know when new events arrive" (not "event arrive")

## Auth Pages (Title Case)
- Auth page headings: "Welcome Back", "Get Started", "Forgot Password", "Reset Password", "Accept Invitation"

## Button Labels (Title Case)
- All button labels use Title Case: "Add Task", "Create Project", "Save Changes"
- Short actions can be single word: "Cancel", "Delete", "Save"

## General Rules
- Never use all-lowercase for headings or labels
- Use "&" instead of "and" in page headings when joining two concepts: "Finance & Billing"
- Use plural for collection pages, singular for detail/create pages
- Accordion headers: "Summary", "Details" (not "Detail")
